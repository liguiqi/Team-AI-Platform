User -> LCUI : 打开 /login
LCUI -> LCPatch : 加载 index.html 注入脚本

alt OPENID_AUTO_REDIRECT=true 且当前路径=/login 且无 query
  LCPatch -> LCUI : 自动跳转 /oauth/openid
else 手工点击
  User -> LCUI : 点击“统一认证登录”
end

LCUI -> LCApi : 发起 OpenID 登录
LCApi -> Redis : 保存 state / code_verifier
LCApi -> Casdoor : /oauth/authorize\nclient_id + redirect_uri + scope + PKCE
Casdoor -> User : 展示登录/注册页\n(themeData + formCss + logo + favicon 已仓库化)

alt 邮箱注册/邮箱验证码登录
  User -> Casdoor : 输入邮箱 / 请求验证码
  Casdoor -> Mail : 发送验证码
else 手机号注册/手机号验证码登录
  User -> Casdoor : 输入手机号 / 请求验证码
  Casdoor -> Sms : 发送短信验证码
else 账号密码登录
  User -> Casdoor : 输入既有账号密码
end

Casdoor -> CasDB : 校验或创建业务用户\n组织 = CASDOOR_USER_ORGANIZATION_NAME\n不是 built-in
Casdoor --> User : 认证成功\n302 redirect 到 LibreChat callback

User -> LCApi : GET /oauth/openid/callback?code=...&state=...
LCApi -> Redis : 校验并恢复 state / code_verifier
LCApi -> Casdoor : /token\ncode + code_verifier
Casdoor --> LCApi : access_token + id_token + refresh_token
LCApi -> Casdoor : /userinfo
Casdoor -> CasDB : 读取 claims / profile / phone / email
Casdoor --> LCApi : userinfo + claims

alt 首次 OpenID 登录且 Mongo 中无用户
  LCApi -> LCApi : 解析 displayName / email / phone / sub
  alt claim 中 email 合法
    LCApi -> Mongo : 按 openidId / email 查找并创建用户
  else 仅手机号或 email 非法
    LCApi -> LCApi : 生成 synthetic email\n避免 LibreChat "email is invalid"
    LCApi -> Mongo : 创建 OpenID 用户
  end
else Mongo 已有本地同邮箱账号且允许关联
  LCApi -> Mongo : 查找 local provider 用户
  LCApi -> Mongo : provider=openid + openidId 迁移关联
else 已有 OpenID 用户
  LCApi -> Mongo : 读取并更新 OpenID 用户资料
end

alt 浏览器命中 LibreChat 重启前的旧 callback
  LCApi -> LCApi : 识别 state 校验失败
  LCApi --> User : 302 /oauth/openid\n自动重发授权
end

LCApi -> LCApi : 写入 JWT / refresh token /\nopenid_id_token cookie
note right of LCApi
openid_id_token cookie 的作用:
- 供 logout 时生成 id_token_hint
- 规避浏览器 / session 丢失时注销失败
end note

LCApi --> User : 建立 LibreChat 会话并跳转聊天页

opt 用户点击“注销”
  User -> LCUI : 触发 Logout
  LCUI -> LCApi : /api/logout
  LCApi -> Casdoor : end_session_endpoint\n附带 id_token_hint
  Casdoor --> User : 回到登录入口或统一认证页
end

  else 配置了 LIBRECHAT_VISIBLE_MODELS
    Admin -> RenderLibre : 触发渲染

    NewAPI -> PG : 校验服务 token / 服务用户 / 渠道
    NewAPI --> RenderLibre : 返回当前可访问模型矩阵
    RenderLibre -> RenderLibre : 与 LIBRECHAT_VISIBLE_MODELS 求交集
    RenderLibre -> Libre : 渲染 models.fetch=false\nmodels.default=白名单交集结果
  end
end

group 用户打开模型下拉框
  User -> Libre : 查看当前可用模型
  alt 当前为动态模式 models.fetch=true
    Libre -> NewAPI : GET /v1/models\nBearer NEW_API_SERVICE_TOKEN
    NewAPI -> Redis : 读取缓存 / 限流辅助信息
    NewAPI -> PG : 读取 token / 用户 / 渠道 / options
    NewAPI --> Libre : 返回当前授权模型列表
  else 当前为前端白名单模式
    Libre -> Libre : 直接显示预渲染模型子集
  end
end

group 聊天请求主链路
  User -> Libre : 发送消息 + 选择当前开放模型
  Libre -> NewAPI : POST /v1/chat/completions
  NewAPI -> Redis : 处理请求计数 / 缓存辅助
  NewAPI -> PG : 校验 token 状态 / 用户额度 /\n渠道状态 / 模型映射 / 系统选项
  NewAPI -> NewAPI : 当前主线使用直通模型名\n必要时再做别名 -> 实际模型映射
  NewAPI -> LLM : 转发到真实供应商 API
  LLM --> NewAPI : 返回标准响应或错误
  NewAPI --> Libre : OpenAI-compatible 响应
  Libre -> Mongo : 持久化 conversation / message /\nagent / prompt refs / uploads
  Libre --> User : 流式展示回答
end

note right of NewAPI
当前分支的关键治理策略:
- LibreChat 不直接接触 ZHIPU_API_KEY
- 服务 token 是 LibreChat 调用 NEW-API 的唯一内部凭证
- 当前主配置以 .env / bootstrap 同步的 19 模型矩阵为准
- 前端若只展示部分模型, 只做“显示过滤”, 不改变 NEW-API 真正权限边界
end note
